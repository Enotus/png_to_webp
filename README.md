# png-to-webp

Рекурсивная конвертация изображений в формат **WebP** на Node.js. Под капотом — `sharp` (libvips), параллельная обработка через `p-limit`, прогресс-бар `cli-progress`, цветной вывод `chalk`.

## Возможности

- Рекурсивный обход директорий с сохранением структуры папок
- Параллельная обработка с настраиваемой конкурентностью (по умолчанию = число ядер CPU)
- Поддержка lossless-режима, контроль `quality` и `effort`
- Опциональное масштабирование (`--max-width`) с сохранением пропорций
- Пропуск уже сконвертированных файлов
- Прогресс-бар: текущий файл, %, скорость, ETA
- Итоговая статистика: количество файлов, размер до/после, экономия, время
- Лог ошибок в `errors.log`
- Корректная обработка `Ctrl+C` (SIGINT) с выводом статистики уже обработанного

## Установка

Требуется Node.js ≥ 18.

```bash
npm install
```

## Использование

```bash
node src/index.js --input ./images [опции]
# или
npm start -- --input ./images
```

### Аргументы CLI

| Флаг | Сокращение | По умолчанию | Описание |
|------|-----------|--------------|----------|
| `--input` | `-i` | — *(обязательный)* | Папка с исходными изображениями |
| `--output` | `-o` | рядом с оригиналом | Выходная папка (структура исходных папок сохраняется) |
| `--quality` | `-q` | `80` | Качество сжатия 1–100 |
| `--lossless` |  | `false` | Сжатие без потерь |
| `--effort` | `-e` | `4` | Уровень компрессии 0–6 (выше — меньше файл, но медленнее) |
| `--keep-original` |  | `true` | Сохранять оригиналы |
| `--skip-existing` |  | `true` | Пропускать уже сконвертированные файлы |
| `--formats` |  | `jpg,jpeg,png,gif,tiff,bmp,avif` | Список расширений через запятую |
| `--max-width` |  | — | Максимальная ширина в пикселях (с сохранением пропорций) |
| `--concurrency` | `-c` | число ядер CPU | Количество параллельных операций |

## Примеры запуска

### 1. Максимальное качество (lossless)

Полностью без потерь — годится для архивации и работы с графикой, где важна каждая деталь.

```bash
node src/index.js -i ./photos -o ./photos-webp --lossless --effort 6
```

### 2. Баланс качества и размера (рекомендованный)

Хороший пресет «на каждый день»: визуальное качество практически неотличимо от оригинала, размер — заметно меньше.

```bash
node src/index.js -i ./photos -o ./photos-webp --quality 80 --effort 4
```

### 3. Максимальное сжатие

Для веб-картинок, которым важна минимальная масса. Чуть медленнее, но самый компактный результат.

```bash
node src/index.js -i ./photos -o ./photos-webp --quality 60 --effort 6
```

### 4. С уменьшением больших картинок до 1920px

Удобно для подготовки изображений к публикации в вебе: обрезаем по ширине, не растягивая мелкие.

```bash
node src/index.js -i ./photos -o ./photos-webp --quality 80 --max-width 1920
```

### 5. Конвертация на месте с удалением оригиналов

> ⚠️ Удаляет исходники. Используйте на резервных копиях или с осторожностью.

```bash
node src/index.js -i ./photos --keep-original false
```

### 6. Только PNG-файлы

```bash
node src/index.js -i ./icons -o ./icons-webp --formats png --lossless
```

### 7. Принудительная переконвертация

Игнорировать ранее сконвертированные `.webp`:

```bash
node src/index.js -i ./photos -o ./photos-webp --skip-existing false
```

## Подсказки по `quality` и `effort`

- **`quality`** влияет на визуальное качество и размер. Для фотографий 75–85 — оптимум.
- **`effort`** влияет только на _скорость_ кодирования, не на качество. Чем выше — тем плотнее упаковка, но дольше работа. На больших объёмах используйте `4`; для финальной публикации — `6`.
- **`--lossless`** игнорирует `quality`, но `effort` всё ещё влияет на размер.
